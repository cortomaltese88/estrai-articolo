# Contributing

Contributi via pull request sono preferiti.

## Linee guida

- Mantenere le modifiche piccole, motivate e verificabili.
- Evitare refactor generali o cambiamenti architetturali non richiesti.
- Non inserire dati reali, dati cliente, documenti riservati o esempi provenienti da casi effettivi.
- Non committare artefatti di build, pacchetti, archivi o file temporanei locali.
- Usare esempi sintetici e minimali per riproduzioni o verifiche.
- Aggiornare la documentazione solo se il cambiamento modifica davvero il comportamento o l'uso del progetto.

## Ambito preferito delle PR

- correzioni mirate;
- miglioramenti documentali;
- verifiche o affinamenti circoscritti;
- aggiornamenti limitati e facili da controllare.
